# EEG 眨眼检测程序

从脑电（EEG）数据中检测**眨眼**事件，输出**每次眨眼发生的时间**。
只需"是否眨眼"，不区分眨眼类型；一次眨眼报告后 **400 ms 内不再重复检测**（不应期）。

---

## 4. 数据格式（数据模板）

见 `data_template.csv`。要求很宽松：

- **分隔符**：`;`、`,`、`\t` 都能自动识别（模板用 `;`）。
- **编码**：`utf-8` / `utf-8-sig` / `gbk` 自动识别。
- **必需列**：
  - 一列**时间（秒）**——列名含 `Time` 或 `时间`；没有则默认取第 1 列。
  - 至少 **1 个 EEG 通道**；**强烈推荐 2 个前额通道**（名字以 `FP` 开头，如 `FP1`/`FP2`），
    因为程序的核心判据需要两个通道互相印证。
- **可选列**：采样率列（列名含 `Sampling Rate` 或 `采样率`），只写第一行也行。
- 其它列（如 `Channel 3..11`）会被自动忽略：
  - 恒定不变的列（饱和 / 未接电极）自动丢弃；
  - 时间列与采样率列自动排除；
  - 若存在 `FP` 开头的通道，优先只用这些通道。

模板示例（前 3 行）：

```
Time (s);FP1;FP2;Sampling Rate
0.0000000000e+00;7.9...e+03;-8.0...e+03;250
4.0000000000e-03;...
```

> 时间戳**不必均匀**：程序会用时间列插值重采样到均匀网格
> （`S00_data.csv` 里就混有 1/256 s 与 5/1024 s 两种间隔，属正常处理范围）。

## 5. 参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `input` | `data_template.csv` | 输入 CSV 路径 |
| `--fs` | 自动 | 采样率(Hz)，覆盖文件里标注的值 |
| `--k` | `3.0` | 阈值系数（单位：稳健标准差）。**越大越严格**，误检越少、漏检越多 |
| `--gate` | `2.0` | 双通道同向门限。两个通道都要超过它，才认为"两路同时看到了同一次偏转" |
| `--refractory` | `0.4` | 不应期(秒)。一次眨眼后该时间内不再重复检测 |
| `--polarity` | `auto` | 眨眼极性：`auto` 自动判定 / `neg` 负向 / `pos` 正向 / `both` 正负都算 |
| `--no-consistency` | 关 | 关闭"双通道一致"要求（仅单通道数据时才需要） |
| `--band` | `0.5,8.0` | 带通频段(Hz) |
| `--out` | `./blink_results.csv` | 结果 CSV 路径 |
| `--plot` | 关 | 额外输出波形标记图 PNG |
| `--make-template` | — | 生成数据模板后退出 |

## 6. 输出

**控制台**：总次数 + 每次眨眼的时间（秒），例如

```
共检测到 30 次眨眼：
  序号   眨眼时间(s)      开始(s)        结束(s)        时长(ms)
  1    4.388        4.332        4.448        116.0
  ...
```

**结果文件** `blink_results.csv`：

| 列 | 含义 |
| --- | --- |
| `blink_index` | 序号 |
| `blink_time_s` | **眨眼时间（秒）** ← 你要的"什么时候眨眼" |
| `onset_s` / `offset_s` | 事件起止时间 |
| `duration_ms` | 持续时长（毫秒） |
| `peak_score_sd` | 峰值强度（稳健标准差倍数，越大越明显） |

## 7. 检测原理（为什么这样判）

眨眼由眼球/眼睑运动产生，是一个**很强的远场电位**，会**同时**出现在左右前额电极上
（方向相同、量级相当）；而肌电、电极噪声、运动伪迹往往**只出现在单个通道**，
或两通道方向相反。

于是程序构造"双通道同向"得分：

```
z1, z2 = 两个前额通道带通(0.5–8 Hz) 后 / 各自稳健标准差(1.4826·MAD)
同向门限：(polarity*z1 > gate) 且 (polarity*z2 > gate)   # 两路必须同向，且都超过 gate
score  = max(polarity*z1, polarity*z2)                    # 取较强的一路作为幅度
眨眼   = score > k（默认 3.0），且与上一次眨眼间隔 ≥ 400 ms
```

两个阈值分工不同：

- `gate`（默认 2.0）保证"是两路**同时**看到的**同一次**偏转"——
  排除单侧电极伪迹、反相漂移、正负不一致的跳变；
- `k`（默认 3.0）保证"幅度足够大"——排除基线上的随机起伏。

**为什么不直接用"两路取较小值"(min)？** 那要求两路幅度**都**达到 3σ。
实测在 20 名受试者、558 个真值眨眼上，min 判据的召回天花板只有 0.903：
有的受试者一侧电极接触较差（如 S14，两路相关仅 0.57），真眨眼在弱通道上只到 2–3σ，
被 min 整批否掉。改成"同向门限 + 取较强一路"后，弱通道只要也超过 2σ 就放行，
**F1 从 0.895 提升到 0.938**（TP +23、FP −25，两头都变好）。

**极性判定**：取"双通道一致"的最强 20 个事件，做**幅度加权符号投票**锁定多数方向，
因此不用手动指定正负。不用"整段能量谁大"——大幅正向伪迹会盖过眨眼，
实测会把 S05/S10 判反（两名受试者的真值眨眼 100% 是负向）。

**伪迹排除实例**（`S00_data.csv`）：11.5 s 处有一个 FP1 单独 +14σ 的伪迹（FP2 几乎为 0），
"任一通道超阈"的做法会误报；同向门限判据把它自然排除。

## 8. 验证结果（EEG-IO 全部 20 名受试者 / 558 个真值眨眼）

数据来源：公开数据集 **EEG-IO**（Agarwal & Sivakumar, *BLINK: A Fully Automated
Unsupervised Algorithm for Eye-Blink Detection in EEG Signals*, Allerton 2019），
前额 `Fp1`/`Fp2`，250 Hz；真值取官方 `*_labels.csv`。

评估口径：检出与真值中点相差 ≤ 0.3 s 记为命中；落在标签标注的 `corrupt` 区间内的检出
单独统计、不计入误检。复现：

```powershell
py evaluate.py ..\..\EEG-EyeBlinks\EEG-IO --tol 0.3
```

| 指标 | 数值 |
| --- | --- |
| 真值眨眼 | 558 |
| 检出 | 576 |
| TP / FN | 526 / 32 |
| 误检 FP | 38（另有 12 个检出落在标注损坏区间内） |
| **recall** | **0.943** |
| **precision** | **0.933** |
| **F1** | **0.938** |
| 命中眨眼的绝对时间误差（中位） | **0.023 s** |
| F1 = 1.000 的受试者 | 3 名（S08、S09、S17） |
| recall ≥ 0.96 的受试者 | 13 名 |

容差敏感性（同一批数据）：

| 容差 | recall | precision | F1 |
| --- | --- | --- | --- |
| ±0.15 s | 0.928 | 0.918 | 0.923 |
| ±0.25 s | 0.939 | 0.929 | 0.934 |
| ±0.30 s | 0.943 | 0.933 | 0.938 |
| ±0.50 s | 0.950 | 0.940 | 0.945 |

逐受试者明细可用 `py evaluate.py ..\..\EEG-EyeBlinks\EEG-IO --tol 0.3 --csv out.csv --md report.md` 随时重新生成。

**剩余误差主要来自 3 名受试者**

| 受试者 | recall | 原因 |
| --- | --- | --- |
| S14 | 0.733 | 一侧电极明显偏弱（两路相关 0.57，弱通道中位幅度仅 3.8σ），12 次眨眼在一侧几乎不可见 |
| S12 | 0.840 | 眨眼整体幅度小（3.3–4.1σ），靠近阈值 |
| S03 | 0.846 | 同上（3.0–3.7σ），且该段有 2 个检出落在损坏区间内 |

**调参建议**

- 想更干净：`--k 3.5`（F1 略降，FP 从 38 降到 30 上下）。
- 想更灵敏：`--k 2.5`（recall 可到 0.96 以上，FP 翻倍）。
- 弱电极受试者可单独用 `--gate 1.5` 放宽同向门限。
- 若你的数据眨眼是正跳：`--polarity pos`（或先跑默认 `auto` 看它判成什么）。
- 若只有 1 个前额通道：`--no-consistency`（自动退化为单通道幅度判据）。

## 10. 已知限制

- 检测基于**幅度 + 双通道同向一致性**，不区分眨眼与"很宽的强运动伪迹"。
  若需要进一步排除，可对 `duration_ms` 设上限过滤（例如 `duration_ms > 700` 视为伪迹）。
- 阈值是**全局**的（整段数据一个阈值）。若数据各段幅度差异极大，
  可分段运行，或改用局部（滑窗）归一化。
- 一侧电极接触不良时（两路相关 < 0.6），弱通道上的眨眼可能低于 `gate`；
  这类受试者建议 `--gate 1.5`。
- 约 5% 的真值眨眼（24/558）在**两路**都达不到 3σ，属于信号本身过弱，
  任何纯幅度阈值都无法找回；这批数据下 recall 的天花板约 0.957。
- 程序也能读**无表头的 OpenBCI 原始格式**（前 5 行 `%` 注释、无列名、第 0 列是采样序号，
  自动换算成秒）。但本工作区的 `EEG-VR` / `EEG-VV` 文件疑似被截断：
  `S00R_data.csv` 有 96558 行却只有 10001 个连续采样点（第 0 列出现 1890 处归零），
  且标签跨到 198.56 s 而数据只到 40 s，**不能用来自证精度**，故这两个子集未纳入评估。
