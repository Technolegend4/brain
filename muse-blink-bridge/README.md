# Muse 实时眨眼桥接器（muse-blink-bridge）

把 **Muse S / Muse 2 脑电仪**的眨眼信号，**实时**转换成网页游戏「眨眼小鸟 / Blink Bird」能识别的事件，实现「**眨眼 → 小鸟振翅**」的完整闭环。

整条链路是**流式实时**的，不落盘、不先保存再回放：

```
眨眼 → Muse 蓝牙实时流 → 本桥接器实时检测 → WebSocket 实时推送 → 小鸟振翅
```

> 固有检测延迟约 0.3~0.5 秒：这是眨眼信号本身持续时长 + 滤波群延迟造成的，属于脑电眨眼的物理极限，不是"先存再传"。

---

## 一、文件说明

| 文件 | 作用 |
|---|---|
| `muse_realtime_bridge.py` | 主桥接器：BrainFlow 直连 Muse + 实时检测 + WebSocket 推送 |
| `blink_detector.py` | 复用的眨眼检测算法（与 `outputs/blink-detector` 同款，已用 EEG-EyeBlinks 数据集评估） |
| `requirements.txt` | Python 依赖清单 |

---

## 二、安装依赖

```powershell
# 建议先确认 Python 版本（brainflow 对新版本支持可能滞后，3.9~3.12 最稳）
python --version

pip install -r requirements.txt
```

> 如果你的 Python 太新（例如 3.14）导致 `pip install brainflow` 找不到对应 wheel，建议装一个 Python 3.11/3.12 再执行。

---

## 三、先跑自检（强烈建议，不需要设备）

这一步**不连任何硬件**，用合成 EEG 验证「桥接器 → 检测 → 网页」整条链路是通的：

```powershell
py muse_realtime_bridge.py --selftest
```

看到下面输出就说明桥接器已就绪：

```
[bridge] 监听 ws://127.0.0.1:8765  （请到网页把「数据来源」选为「Python 桥接器(WebSocket)」…）
```

然后打开网页游戏：

1. 左侧「数据来源」下拉选 **Python 桥接器（WebSocket）**；
2. 桥接器地址保持 `ws://127.0.0.1:8765`；
3. 点 **连接并开始**。

如果一切正常，你会看到日志区持续弹出 `→ 眨眼 @ t=…s`，小鸟会随合成眨眼振翅——说明链路打通了，可以进入真实设备阶段。

## 四、连接真实 Muse（BrainFlow 直连）

### 4.1 准备工作

1. **给 Muse 开机**：长按头带侧键，指示灯进入呼吸/闪烁状态。
2. **在 Windows 里配对**：打开「设置 → 蓝牙和其他设备」，搜索到 `Muse-XXXX` 并配对（通常无需 PIN）。
3. **彻底退出 XMuseLab**：Muse 蓝牙是独占的，同一时间只能一个程序连接。务必完全退出 XMuseLab，否则直连会失败。
4. **（可选）记下蓝牙 MAC**：印在头带左耳后传感器附近，形如 `00:55:DA:B0:XX:XX`。用它直连更稳。

### 4.2 启动

```powershell
# 自动发现已配对的 Muse S（默认 board_id=38）
py muse_realtime_bridge.py

# 指定 MAC，连接更稳
py muse_realtime_bridge.py --mac 00:55:DA:B0:XX:XX

# 如果你的设备其实是 Muse 2
py muse_realtime_bridge.py --board 22
```

看到采样率 256 Hz、AF7/AF8 通道信息，并进入监听状态即成功。

### 4.3 打开网页

同第三节：数据来源选「Python 桥接器（WebSocket）」，地址 `ws://127.0.0.1:8765`，点「连接并开始」。

此时你**正常眨眼**，小鸟就会随之振翅。

## 五、常见问题排查

| 现象 | 原因 / 处理 |
|---|---|
| 连接失败：BrainFlow 连不上 Muse | Muse 没开机 / 没在系统蓝牙配对 / XMuseLab 还开着 / 设备不是标准 Muse S，试 `--board 22` |
| 连上了但网页收不到事件 | 网页「数据来源」没选 WebSocket；或地址不是 `ws://127.0.0.1:8765` |
| 一直不报眨眼 | 阈值过高，可调低 `--k 2.5`；或眨眼极性判定没锁定，多自然眨几次；或电极没贴好前额 |
| 小鸟乱跳/误触 | 阈值过低，调高 `--k 3.5`；或前额没贴紧、有皱眉/肌肉动作干扰 |
| 延迟感觉偏大 | 正常范围 0.3~0.5s；可把网页里「映射模式」设为「一次眨眼=一次跳」感受更直接 |
| `pip install brainflow` 装不上 | 换 Python 3.11/3.12 再装 |
| 控制台中文日志乱码 | 先执行 `chcp 65001` 再运行脚本即可正常显示 |

## 六、原理简述

- **数据获取**：BrainFlow 通过 BLE 直连 Muse，读取前额两个通道 **AF7/AF8**（眨眼伪迹在此最强），采样率 256 Hz，单位 µV。
- **实时检测**：维护 2.5 秒滑动窗口，每 100ms 对窗口跑一次 `blink_detector.py` 的成熟算法（带通 0.5–8Hz + 稳健标准化 + 双通道同向门限 + 自动极性锁定 + 不应期）。
- **去重**：用「绝对样本序号」判断哪些眨眼是新的，避免滑动窗口重复报告同一次眨眼。
- **推送**：检测到新眨眼就发 `{"type":"blink","t":…,"score":…,"tPeak":…}` 到 `ws://127.0.0.1:8765`，网页游戏据此让小鸟振翅。
