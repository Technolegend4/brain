# 眨眼小鸟 · Blink Bird

用**前额脑电里的眨眼伪迹**驱动小鸟振翅的浏览器小游戏。
全部算法（滤波、检测、物理、渲染、音效）在页面本地运行，零第三方依赖、数据不上传。

```
EEG 原始信号(Fp1/Fp2)
   → 因果带通 0.5–8 Hz + 50 Hz 陷波
   → 滑动稳健基线(MAD) → z 分数
   → 双通道同向合成 → 双阈值状态机 → 眨眼事件
   → 小鸟起跳（含 0~450 ms 延迟回溯补偿）
```

## 快速开始

**方式一：一键启动（macOS）**

双击 `start.command`，浏览器会打开 `http://127.0.0.1:8080/blink-flappy/index.html`。

**方式二：手动**

```bash
cd blink-flappy
python3 tools/serve.py          # 默认 8080，自动开浏览器
python3 tools/serve.py 9000     # 指定端口
python3 tools/serve.py --no-open
```

**方式三：直接打开**

`index.html` 也可以双击直接跑（合成 / CSV / WebSocket 三种源都行），只有 Web Serial 需要 http 环境。

> 首次体验建议：信号源选 **合成 EEG** → 点「连接并开始」→ 按 **空格** 注入眨眼。
> 没有设备也能跑通完整闭环。

## 把脑电数据丢进去会怎样

界面是「上面游戏、下面脑电波形」的工作台形态。载入数据后全自动：

1. 解析 CSV（分号表头 / OpenBCI 两种格式都能认）
2. 自动连上信号源，小鸟立刻起飞
3. 每检测到一次眨眼，小鸟振翅一次
4. 撞到管道 1.5 秒后自动重开，回放期间不会停在结算页

波形区画三条通道 —— **FP1 (z)**、**FP2 (z)**、**检测分数**，每条有独立基线和中线。检测到的眨眼用一条贯穿所有通道的竖线标出，顶部三角和 `BLINK` 字样；线越粗、颜色越偏琥珀，说明这次眨眼越有力。分数道上的橙色虚线是当前触发阈值。

下方还有回放进度条和「检出眨眼」计数，速度可在 **1×–8×** 之间调，数据再长也不用干等。

## 四种信号源

| 信号源 | 需要什么 | 说明 |
|---|---|---|
| **合成 EEG** | 无 | 1/f 背景 + 基线漂移 + 50 Hz 工频 + 双指数眨眼模板，用于验证链路 |
| **回放本地 EEG CSV** | 一个 CSV | 支持 `EEG-EyeBlinks` 的两种格式；点「用数据集示例」可直接加载 `EEG-IO/S00_data.csv` |
| **OpenBCI 串口** | OpenBCI + Chromium 系浏览器 | Web Serial 读 33 字节二进制包（0xA0…0xC0），需 Chrome/Edge/DeepWorks 浏览器 |
| **Python 桥接器** | Python 3 | `tools/bridge.py` 在服务端做检测，用 WebSocket 把事件推给页面 |

> **Safari 不支持 Web Serial**，请用合成 / CSV / WebSocket 三种源之一。

### 用 Python 桥接器（零依赖）

```bash
cd blink-flappy

# 1) 离线检测：CSV → jumps.json
python3 tools/bridge.py detect "../EEG-EyeBlinks 5/EEG-IO/S00_data.csv"

# 2) 起 WebSocket，按原始时间轴推给网页
python3 tools/bridge.py serve jumps.json --port 8765 --speed 1.0

# 一步到位（检测完直接起服务）
python3 tools/bridge.py detect 某个.csv --serve --speed 2.0
```

页面端：信号源选「Python 桥接器（WebSocket）」，地址保持 `ws://127.0.0.1:8765`，点「连接并开始」。

## 四种「眨眼 → 动作」映射

| 模式 | 行为 | 适合 |
|---|---|---|
| **辅助振翅 + 眨眼加成**（默认） | 自动驾驶维持高度，眨眼额外拉高并加速 1 秒 | 检测精度一般也能玩，推荐首次使用 |
| **一次眨眼 = 一次跳** | 完全靠眨眼，不眨眼就掉下去 | 检测率高（>85%）时的纯粹体验 |
| **闭眼上升 / 睁眼下落** | 眨眼期间持续升力 | 能稳定保持闭眼的使用者 |
| **眨眼开关节拍** | 眨眼切换自动驾驶开关 | 疲劳、眨眼频率低时 |

眨眼的**力度**会直接变成升力：z 峰值越高，跳得越高、辅助模式下抬升持续越久（±20%）。
同一个动作有轻重之分，比"二值按键"更有身体感。

其余可调项：

- **触发阈值 k**：3.4 σ 起步（真实数据 F1 最优区间 3.4~3.6）。误跳多就调高（4.0~5.0），漏检多就调低（2.4~3.0）。
- **不应期**：默认 300 ms。标签里 98% 的相邻眨眼间隔 > 0.4 s，300 ms 已足够，也能少吃掉连眨；连跳太密可加到 600 ms。
- **自适应难度**：按最近 30 秒实测眨眼率调整管道间隙与速度。
- **校准**：双击右侧波形区域，采集 8 秒静息背景，按 99.5% 分位自动定阈值。换人、换电极、换姿势后建议重新校准。

当前实测结果：

| 测试 | 指标 |
|---|---|
| 合成信号 120 s（固定随机种子，可复现） | recall 90.3%，precision 100%，峰值延迟中位 70 ms |
| 真实数据 `EEG-IO/S00` | recall 84.0%，precision 72.4% |
| 滤波器 | 50 Hz 陷波 −240 dB，20 Hz 低通 −15.3 dB |

**全数据集（2035 个标注眨眼，容差 0.3 s）**

| 子集 | 被试 | recall | precision | F1 |
|---|---|---|---|---|
| EEG-IO（刺激诱发） | 20 | 0.864 | 0.888 | 0.876 |
| EEG-VR（看视频） | 13 | 0.928 | 0.913 | 0.920 |
| EEG-VV（看视频） | 13 | 0.864 | 0.849 | 0.856 |
| **合计** | **46** | **0.885** | **0.881** | **0.883** |

> **评估口径**：VR/VV 的标签只覆盖每个文件的前约 200 s，而数据有 300~430 s。
> 统计时必须排除标签范围之外的检测，否则大量"未标注但真实"的眨眼会被算成误检
> （不排除时 precision 会虚低到 0.44~0.48）。上表已按标签范围截断。

> **演示建议**：三个子集都可直接用；用「辅助振翅」模式容错最高。

**游戏触发路径和统计路径不是同一条**

- `blink` 事件：等波形回落后才确认，最准，用于计数/眨眼率
- `onset` 事件：上升沿就报，延迟最低，用于驱动游戏

为了让"没眨眼鸟也跳"尽量少，onset 上加了两个闸门：

| 参数 | 值 | 作用 | 代价 |
|---|---|---|---|
| `onsetConfirm` | 3 样本（12 ms） | 连续 3 个样本都超阈才算真上升沿 | 延迟 +12 ms |
| `onsetBoost` | 1.10 | onset 要求峰值超出阈值 10%，擦线的短促眼动不触发游戏 | 召回 −1~4 点 |

`onsetBoost` 在界面上就是「游戏灵敏度」滑块（0.9~1.8）。调高 → 误跳少、漏跳多；调低 → 更灵敏、更容易乱跳。

| 路径 | EEG-IO R / P | EEG-VR R / P | EEG-VV R / P |
|---|---|---|---|
| blink（统计） | 86 / 89 | 92 / 91 | 85 / 85 |
| onset（游戏） | 83 / 85 | 94 / 90 | 85 / 84 |

净效果：误触发从 18% / 13% / 21% 降到 15% / 10% / 16%，端到端延迟仍在 150 ms 以内。

## 已知限制

1. **单次眨眼的绝对时刻不可辨**：检测输出的是"眨眼峰值"，与标注的"眨眼中心"存在 20~70 ms 系统偏差。做研究比对时需按容差匹配，不要逐点求差。
2. **超长闭眼会被漏掉**：`maxDurMs = 700 ms` 之后强制结束事件，超过 0.7 s 的闭眼算一次。
3. **双通道假设**：算法依赖两路前额电极同向出现偏转来排除单侧伪迹。只有单通道时精度会下降，需改 `consistency` 相关参数。
4. **CSV 回放是"离线数据实时重放"**：用的是文件里的波形，不是现场采集，用于演示与调参。
5. **暂停不会重连**：暂停时串口与 WebSocket 保持连接、只丢弃数据，因此暂停期间的事件不会补发。要重放请点「停止」再「连接并开始」。
6. **极性纠正需要几秒**：极性判反时会自动翻转，但判据是"反向峰强度连续比正向事件强一倍以上，且至少 3 次"，通常要 10~20 秒才能确认。翻转后 30 秒内不再翻转，避免来回抖。
7. **CSV 解析分片进行**：`EEG-VV` 单文件约 96k 行，按 4000 行一批让出主线程，解析期间面板会显示百分比（不再整页冻结）。
8. **表头列名会影响通道选择**：优先按 `Fp1`/`Fp2` 匹配，其次取前两路"有效数值过半"的列；时间列和采样率列会被自动排除，全文本列（如 Subject ID）也不会被误当成信号。
9. **个别被试信号质量差**：`EEG-VV/S10V` 的两通道相关性只有 0.41（其余被试 0.85~0.99），召回仅 36%，拉低了 VV 的整体数字。这是数据质量问题（电极/参考异常），不是算法退化——同一个检测器在其余下 12 个被试上的召回约 92%。
10. **不做医学用途**：本项目是交互演示，不构成任何诊断或医疗建议。
